# V2 preparation and execution protocol

Apply the existing V1 discipline and [V2 contract](../../templates/IMAGINE_SHOT_CARD_V2.md).

1. Inventory canon, game events, prior QC and visual sources. Reference pools are not bind lists.
2. Define physical camera address, cast instances, fixture before/after maps,
   contact, consequence and endpoint. A crop is not a new camera angle.
3. Prepare a complete full-frame opening with cast, grip and current room state.
   Show exact filename/hash to the owner. Never composite cutouts into delivery.
4. Record the explicit owner decision with opening hash and current plan fingerprint.
   A producer assertion, boolean or old crop approval is not this receipt.
5. Compile two-to-four accepted images into canonical SHOT_PACKET.json. IMAGE_1
   is the complete opening. Large ensembles need a separately approved single-scene
   ensemble identity authority within the image budget, not a multi-panel sheet.
   Preserve simultaneous teamwork; do not substitute isolated static solos.
6. Verify recipient access, image/request/prompt hashes, attempt cap, no HOLD,
   and both V2 and canonical Imagine readiness gates.
7. Execute one shot/action and at most one move. Short duration is not drift immunity.
8. Return native bytes and matching request lineage. Review full playback and
   exact suspect frames; sampled first/contact/end checks are not acceptance.
9. Publish each revision and QC before waiting for a return. Codex private access
   is not Grok access; require ACCESS_ACK. Do not change repository visibility.

## State and stop rules

- Coverage uses separate COV-* IDs and cannot fulfill acted SHOT-* beats.
- Empty preparation plates may have no people; acted openings contain exactly
  the intended visible cast. Hidden/emerging/exiting actors use temporal visibility.
- Prior cleaned surfaces stay clean. Continuous action uses the accepted previous
  endpoint; authored cuts use independently approved matching-state openings.
- Attempt limits are cumulative per lineage. A004 owner-exception assertions
  remain historical; missing A006 REQUEST is not retrospectively invented.
- Full-frame cinematic provenance, human/device/child acceptance and protected
  family voices retain their independent rules. DELIVERY_ACCEPTED stays false.
