# DKC soundtrack profile and listening register

This separate study covers the original 1994 SNES Donkey Kong Country soundtrack. The original in-game sound is the authority. Performer profiles, Bonobo production preferences, General MIDI program labels and available libraries are resources for finding a match; they never require changing the original instrument. Add a patch, articulation, technique or performer capability when the source requires it.

## Current coverage

Research intake dated November 2, 2026, with machine receipts in UTC on November 3. There are 30 review rows: the 29-entry SPC catalog plus Game Over as a coverage reconciliation item. Metadata searches found original-recording candidates for all 30, downloadable MIDI candidates for 24, and possible MIDI videos for 21. None of these counts establishes a faithful backing or accepted instrument match. All listening and fidelity fields remain open.

The [SPC catalog](https://snesmusic.org/v2/profile.php?selected=711&set=) provides the 29-entry spine. The [Nintendo Music catalog description](https://www.mariowiki.com/Donkey_Kong_Country_(Nintendo_Music)) uses 26 album entries and different short-cue groupings. Keep aliases rather than treating album order as the complete runtime inventory. Game Over, opening fanfare, level/bonus outcomes and other short cues remain explicit; death/game-over cues are reference analysis and do not commission fail states for Roshan.

The [track register](soundtrack_catalog.json) preserves both rounds of YouTube search results, queries, titles, channels and durations. The [TMK source receipt](midi_catalog.json) and [VGMusic source receipt](vgmusic_catalog.json) preserve actual resolved URLs, bytes and SHA-256; VGMusic also records sequencer, MIDI track names, note counts, declared programs and percussion-channel presence. A successful MIDI parse proves a usable file, not transcription accuracy. Remixes, orchestral arrangements and piano reductions require classification before use.

## Review sequence and stress tests

1. Confirm each original link is the original SNES performance. Reject restored, remastered, arranged, different-game, PAL-speed or pitch-shifted references unless explicitly classified. Record uploader/title, duration, recording version, listening date, reviewer and reviewed time spans. If an extended upload is used, identify the real first cycle and repeated material.

2. Confirm the MIDI video has the correct piece and all backing parts. Label piano reduction, remix, GM/GS/XG render and partial/stem-only separately. Select a score by source bytes/hash and sequencer. Align its opening, tempo changes, first complete form, returns and ending against the original. Log missing bass, percussion, notes, controllers, pitch bends and section omissions before arranging.

3. For every audible part record: track/section/time span; observed timbre and uncertainty; original sample/channel identifier if available; melodic/harmonic/groove/texture role; register and note lengths; attacks/decays/releases; bends, modulation and velocity response; pan/depth/effects; silence/entry/exit behavior. A MIDI program name is a transcription hypothesis, never proof of the game instrument.

4. Audition up to three exact installed patches per disputed part using the same verified phrase at original register and timing. First compare dry attacks and tails, then source-like effects. Save native REAPER/Falcon state, exact program path/version, active articulation/key switches and rendered audio hashes. Test low/middle/high registers, soft/medium/hard attacks, repeated notes, held notes, legato/overlap, releases and pitch bends. Drum tests cover each actual stroke plus rapid alternation and ghost/accent relationships. Avoid broad humanization until the original groove is understood.

5. Use level-matched reference/candidate A/B at the same excerpt boundaries; record the gain adjustment and keep raw files. Compare first entry, densest passage, exposed part, section return and tail. Check mono, headphones and speaker. Measure clipping, silence, spectrum/envelope, bass register and stereo differences as diagnostics; mix spectra alone cannot identify an instrument. Do not score exact-source fidelity from loudness or a generic timbre label.

6. Recheck the candidate inside the complete arrangement. A good solo patch may mask the lead, erase the bass or add the wrong attack in context. Keep original timing, instrumental hierarchy and electronic colors where audible. If every candidate fails the defining attack/sustain/register/articulation behavior, record a gap and change instrument or method rather than adapting the source to fit the roster.

7. A source match closes only with the exact reference, patch/render hashes, comparison excerpt and named human disposition. Record accepted, rejected or uncertain with reasons. Automated listening is advisory. Owner acceptance of full performances remains separate from patch recall and machine checks.
