## Running tally for the dot

The commissioning chat created the active hourly `flat-vector-art-tally` heartbeat targeted to this chat. Its existing notification policy stays quiet while unchanged. The durable source of tally facts is this published branch/path and `tally.json`; local staging is not delivery. Follow a published request revision/hash and compare exact source hashes before carrying status forward.

1. Read `tally.json`, `per_piece.json`, `per_piece_briefs.json`, `scene_coverage.json` and `MANIFEST.json` from the exact published revision.
2. Report named designs, context families, source scopes and route entries separately. Keep the actual whole-game individual-piece denominator unknown until fully enumerated. Never subtract a raw call site as if it were an accepted design removal.
3. On source/route/hash drift, mark only affected rows for renewed context review, preserve the earlier evidence and re-enumerate newly added art, shaders, glyphs and fallback/build paths. Unknown regressions stay unknown until the repeat census is verified.
4. Record each material revision and automatically publish/verify it under the established handoff authorization. Keep candidate, integrated, runtime-verified and fully accepted removal totals separate. `ACCEPTED_REMOVED` requires every applicable evidence lane and retired recreation/fallback proof.
5. Notify on meaningful progress, regression, completed stage, failure or required user action. Stay quiet while unchanged/non-actionable. Do not describe this initial audit as the zero-vector end condition.

Stable status lanes are stored in the tally: `NEEDS_CONTEXT_REVIEW`, `IDENTIFIED`, `REUSE_READY`, `DRAWING_REQUIRED`, `SAMPLE_READY`, `VISUAL_REVIEW_PENDING`, `APPROVED_FOR_INTEGRATION`, `INTEGRATED`, `RUNTIME_VERIFIED`, `DEVICE_CHILD_OWNER_PENDING`, `ACCEPTED_REMOVED`, `BLOCKED`, `VERIFIED_NOT_FLAT_VECTOR_ART`, `EXEMPT_FUNCTIONAL`, `INACTIVE_ARCHIVE`. A code fallback is not `INACTIVE_ARCHIVE` merely because normal textures usually load. Source/runtime-proved non-flat artwork, invisible functional geometry and truly inactive archive records resolve separately and never count as replacements. Such dispositions require a reason, exact source/guard trace, current visibility review, named reviewer and check time; a favorable quality score cannot exempt flat-vector artwork. Ordinary invisible masks/hitboxes and text rendering can be functional; visible frames/effects and icon art require explicit disposition.
