# Audio audit — what plays, what doesn't, and why

_2026-08-02. Generated by `tools/audit_audio_usage.py` (re-runnable; add
`--json` for machine-readable output). Companion to the decommission wing —
see `decommissioned/MANIFEST.md` § "Audio"._

## Why this audit exists

The decommission pass needed to know which audio was dead. The obvious check —
grep each filename — reports **165 of 186 files as unreferenced**, including
every recorded family voice. That answer is completely wrong, and acting on it
would have deleted irreplaceable audio.

Nothing in this game references audio by filename. Paths are composed at
runtime:

```gdscript
# AudioDirector._say()
var p1 := "res://assets/audio/voices/" + key + ".ogg"      # <speaker>_<event>
var p2 := "res://assets/audio/voices/" + speaker + ".ogg"  # fallback
# AudioDirector._play_music()
var mpath := "res://assets/audio/music/" + fname + ".ogg"
```

So `grep daddy1.ogg` finds nothing because no source file contains that string.
Resolving real usage means reconstructing the **vocabulary** the code can
generate, from five separate sources:

1. `_say("roshan", "win")` — literal call arguments.
2. `_say("roshan", ["idle1","idle2","idle3"][randi() % 3])` — array-literal picks.
3. `show_msg(who, txt, vo)` — routed through `_speaker_key(who)`, which maps a
   display name to a voice key by substring.
4. **Data tables.** The opera career rows carry the line as data:
   `{"speaker": "Faron", "vo": "op_nursery_catch"}` → `faron_op_nursery_catch.ogg`.
   This alone accounts for ~90 files.
5. **The friend roster.** `show_msg(fr["fname"], …)` where `fname` is
   `"Daddy Mermaid"`, `"Wacky and Chuck"`, … from `FRIEND_DEFS` (`main.gd:583`).

## Finding 1 — Daddy Mermaid already has three recordings, and none can play

`voices/daddy1.ogg`, `daddy2.ogg`, `daddy3.ogg` — **UNREACHABLE-NAMING**.

`_speaker_key("Daddy Mermaid")` returns `daddy`, so the resolver looks for
`voices/daddy_<event>.ogg`, then `voices/daddy.ogg`. There is no `daddy.ogg`,
and nothing ever asks for event `1`, `2`, or `3`. All three fall through to the
pitched `voice_yay` stand-in.

This is the opposite of a deletion candidate. You mentioned you can record new
Daddy lines — worth knowing you may not have to: three takes are already sitting
there, mute because of the filename. Compare `roshan_idle1/2/3.ogg`, which *do*
play, because a call site names them explicitly:

```gdscript
_say("roshan", ["idle1", "idle2", "idle3"][randi() % 3])   # main.gd:898
```

Two ways to make the Daddy takes audible, both cheap:

- **Rename** the best of the three to `daddy.ogg` — it immediately becomes the
  fallback for all 5 requested Daddy lines. Keep the other two as-is.
- **Or** add a rotation at the Daddy call sites, matching the Roshan idle
  pattern, so all three play.

I have not renamed anything: `CLAUDE.md` forbids modifying `assets/audio/voices/`
without being asked, and picking which take becomes the canonical one is your
call, not mine.

## Finding 2 — Wacky's four lines are shadowed by Chuck

`voices/wacky.ogg`, `wacky_win.ogg`, `wacky_fail.ogg`, `wacky_splash.ogg` —
**UNREACHABLE-SPEAKER**.

Wacky is never named directly at any call site. The only route to that voice is
the roster entry `{"fname": "Wacky and Chuck", …}` (`main.gd:589`), and
`_speaker_key` tests substrings in order:

```gdscript
if "chuck" in w: return "chuck"      # audio_director.gd:50
if "wacky" in w: return "wacky"      # audio_director.gd:51  ← never reached
```

`"wacky and chuck"` contains both, and `chuck` is tested first — so the pair
always speaks with Chuck's voice and Wacky's four recordings are dead code.

Swapping those two lines makes all four audible, but it also silences Chuck for
that pair, so it is a taste question rather than an obvious bug fix: **who should
speak for "Wacky and Chuck"?** If you want both, the roster needs two entries or
the call sites need to alternate. Unchanged pending your decision.

## Finding 3 — Four minigame music tracks are never started

`music/dolls.ogg`, `seek.ogg`, `shop.ogg`, `treasure.ogg` — **UNUSED-TRACK**.

Each has a matching minigame (`scripts/games/dolls.gd`, `seek.gd`, `shop.gd`,
`treasure.gd`), and none of those four scripts calls `_play_music` at all, so
they play whatever the world track was. The other minigames do switch
(`fetch`, `melody`, `race`, `hall`, `home`, `castle_open`, `finale`, `world`,
`world_night`, `level2` all resolve).

Reads as an oversight rather than a decision — the tracks were made for these
games. One line per game (`m._play_music("dolls")` on entry, restore on exit,
which the other games already model) would use them. Left alone: it changes
shipped audio behaviour and belongs behind a probe run.

## Confidence and limits

- 11 call sites stay unresolved (listed under `UNRESOLVED CALL SITES` in the
  tool output). Nine are `_play_music` with a computed track (`restore_track`,
  `prev_track if … else "finale"`) — these restore a previously-playing track,
  so they cannot introduce a new filename. Two are the `_say`/`show_msg`
  wrappers in `main.gd` that forward to `AudioDirector`, counted at their real
  call sites instead.
- The roster expansion is deliberately an **over-approximation**: a dynamic
  `show_msg(fr["fname"], …)` is credited to every roster speaker. This can mark
  a file used that a specific code path never reaches — the safe direction of
  error for irreplaceable audio.
- `DYNAMIC-ONLY` files are reachable but not provably so from a specific site.
  Treat them as used.
- The audit reads `scripts/` only. Audio referenced from a `.tscn` or a
  generated resource would be missed; none is today (`scenes/` holds one file).
