The common sequence

RequestA valid touch gives prompt visible response and preserves the child’s selected answer/plan.
ArriveRoshan reaches the actual target through current navigation. No remote progress.
WorkThe child’s existing gesture drives the relevant operation; hand/tool makes local visible contact.
FinishRoshan visibly finishes the exact task verb. Do not replace work with a cheer or auto-solve a choice.
SettleSame hands, cuffs, prop, support, costume and room persist; release into a clear stable state.
Show ResultThe actual earned object/state stays visible and consistent with the saved consequence.
Celebrate Or NextCelebrate only after the real finish is legible; retain existing specialist/voice/return ownership.

The final action must be the work itself: the last wrapper twist, the bandage being smoothed onto the arm, the berry placed where it belongs, or the geode opened with its crystals still inside. A cheer cannot stand in for that contact. The child keeps control of choices and gestures.

Why the wrapping currently looks windowed

The inherited activity surface is 392×232 pixels inside a 416×292 card. The reviewed wrapping artwork occupies about 223×223 pixels. That uses only a small part of the 1280×720 game canvas. Teacher, Geologist, Boxer and Racer already have larger or full-stage paths, so the layout is inconsistent.

The fixed-size desktop audit window is a separate capture setting. Enlarging the browser screenshot or changing desktop window mode would not fix the small in-game working area.

Working view and native resolution

The rollout direction is a shared stage-size composition with Roshan and the object readable on the phone. Each career keeps its own room, costume and props. When a closer working view is needed, the same framing and entry/exit grammar applies in story and training.

Backgrounds require at least 2048×2048 native coverage per playable screen. Current complete wrapping review keys are 1672×941. They are useful source studies, but do not meet that background coverage requirement. Padding or upscaling into 2048 tiles does not supply missing native detail. Character and prop cutouts must instead carry enough detail for their measured display size and obey the texture import limits.

A larger working view and higher native-resolution masters are separate requirements. Both need to pass before the replacement is considered ready.
