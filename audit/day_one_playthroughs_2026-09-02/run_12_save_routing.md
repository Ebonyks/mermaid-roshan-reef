# Run 12 — The family phone
Persona: The same 4-year-old, on the same 3–4-year-old Android phone that already carries a `reef_save.json`. She opens the app herself with a parent nearby, cannot read, knows "the two big buttons" but not which is which, and wants to get back to "her castle" and the shiny things she remembers. She taps whatever glows or is gold, and repeats whatever worked last time. This run traces FOUR openings against four saves rather than one long playthrough, and stops each one where she lands and receives her first real prompt.

Path taken: Boot → start menu (`StartMenu.build`, `scripts/start_menu.gd:26-95`) → (a) legacy save + CONTINUE, (b) mid-Day-One save + CONTINUE, (c) finished-Day-Two save + NEW GAME by mistake, (d) four partial/corrupt saves + CONTINUE. Every Continue/New Game path funnels through `_launch_from_start_menu()` → `_prepare_start_menu_launch()` → `_enter_level2_now(false, false, true)` (`scripts/main.gd:3966-3981`, `START_AT_CASTLE_GATE` true at `main.gd:44`), i.e. the Sky Lagoon ocean-gate hub at master x 610 (`scripts/arena/sky_lagoon_promenade.gd:261-262`), then the walk/auto-enter into the castle (`sky_lagoon_promenade.gd:1026-1036`) and the main hall (`main.gd:6819-6860`). Findings first, then the beat log.

**Headline findings (all proven by code unless marked inferred):**
1. **The documented "legacy direct-game route" is unreachable for any real on-disk save.** `SaveState._read_save_candidate` normalises every candidate (`scripts/save_state.gd:430`) and `_normalise_save` merges `DayOneDirector.normalise_save_patch(raw)` (`save_state.gd:526-530`), whose default for a missing `day_one_active` is **true** (`scripts/day_one_director.gd:597-598`). `load_save()` then stores that normalised dictionary as `m.save_data` (`save_state.gd:71-72`) and, because `changed` is true for a save lacking the namespace (`save_state.gd:439`), **rewrites the primary file on disk** with `day_one_active: true` before the child touches anything (`save_state.gd:82-86`). `StartMenu.continue_day_one_mode(m.save_data)` therefore sees the key present and true (`start_menu.gd:19-21, 243`) and routes a pre-Day-One save into Day One. The comments at `start_menu.gd:241-242` and `main.gd:3967-3969` promise the opposite. `probe_start_menu_routing.gd:20-21` passes only because it feeds the static function a raw `{"legacy": true}` dict that never passed through `SaveState`. Only a save that explicitly stores `day_one_active: false` (i.e. one that already finished Day Two, `day_one_director.gd:439-447`) gets the direct route. **Consequence for opening (a): the family's old castle becomes dirty, every non-Day-One door "rests", jobs and the Opera House lock (`scripts/castle_career_routes.gd:114,142,184,304,313`; `main.gd:3361-3366`).** Progress data (pearls, friends, companion, opera stars) is retained, but access is not.
2. **NEW GAME is a two-tap, text-only, gold-then-gold wipe with no voiced or pointed confirmation and no restore path a family can actually use.** `_request_new_game` shows a panel whose title/note are text (`start_menu.gd:214-229`), whose confirm button is the SAME gold style as the button she just tapped, sits 168 px straight above it (NEW GAME rect 650,548 340×118 vs START NEW 660,380 300×118, `start_menu.gd:81-82, 233-234`), and receives keyboard/gamepad focus (`start_menu.gd:262-264`). No `_say()`, no pointer, no delay. `start_new_game()` archives the old document to `reef_save.json.before_new_game` (`save_state.gd:298`), but nothing in the game, `backup.sh` (`backup.sh:64-68` pulls only `.json` and `.bak`) or `BACKUP.md` (only the `adb run-as` recipe at `BACKUP.md:64-71`, for a backup.sh snapshot) restores it; a second accidental New Game overwrites the archive (`save_state.gd:298`).
3. **Reset path `DAY_ONE_AFTER_RESET_META`** (`start_menu.gd:8, 30-34, 274-275`): the marker lives on `SceneTree.root`, survives `reload_current_scene`, and on the next `build()` skips the menu and calls `_launch_from_start_menu(true)`. The reload re-runs the full `_ready` world build (`main.gd:986-1078`) behind the boot splash (`scripts/boot_splash_overlay.gd:9,36`, 0.45 s handoff after build). The arrival "replays" only as the in-engine fallback: the runway plane card is rebuilt because the fresh save has no `lagoon_plane_departed` (`sky_lagoon_promenade.gd:499-509`), bobs ±0.12 px for 7.0 s (`:33, 1038-1047`) and is then freed and replaced by the smaller reef marker with a save write (`:1049-1068`). `trigger_arrival_plane_media()` fires once and only records `g["day_one_media_request"]` (`main.gd:7335-7337, 7775-7779`). No flight animation and no movie exist.
4. **`normalise_save_patch` cannot trap her on ordinary partial saves** — completed rooms are re-derived in order and current room is the first gap (`day_one_director.gd:541-551`), the art desk is derived from the seven actions (`:589-595`), boss glow is derived from all-four-complete (`:611`). **But one real state is a dead end:** `day_one_active: true` + all four rooms complete + `day_one_giant_dust_bunny_boss_triggered: true` — exactly what is on disk the instant the Grand Puff fight starts, because `_write_save()` runs BEFORE `_start_game` (`main.gd:7794-7798`). If the app is killed, backgrounded-and-evicted, or the fight is left without a win, restore keeps `triggered` true (`day_one_director.gd:612-613`; asserted as intended at `scripts/probe_day_one_director.gd:91-98`), `day_one_boss_door_ready()` is false (`main.gd:7069-7072`), `_day_one_arm_boss_door()` returns early (`:7763-7765`), the royal hall is BLOCKED (`scripts/castle_door_language.gd:47-48`), no door highlights (`:67-73`), `trigger_giant_dust_bunny_boss()` refuses forever (`day_one_director.gd:429-430`), and nothing resets the flag (only writers: `day_one_director.gd:133, 431, 511`). Jobs and opera stay locked. The only exit is the reef "Dusty Attic" portal (`main.gd:1063, 5373-5374, 5491-5493, 10004-10007`), whose win calls `day_one_complete_boss_and_begin_day_two()` (`scripts/games/dust_boss.gd:609`) and needs only `day_one_active` (`day_one_director.gd:439-447`) — but no pointer or voice line sends her there.
5. **Continue never lands her where she was.** Every launch lands in the lagoon at the runway end (`main.gd:3971-3972`, `sky_lagoon_promenade.gd:261`), where the first and only prompt is the reef plane glow + "Tap the pearl plane to visit the Reef!" + `roshan_intro4.ogg` (`sky_lagoon_promenade.gd:266-269, 1077-1083`; `scripts/audio_director.gd:169-173`), pointing AWAY from Day One. The castle is off-screen (view width 1280/(720/2048) ≈ 3641 master px, camera clamped to 1820 at spawn, `sky_lagoon_promenade.gd:991-997`; castle card at 5260, `:556-560`). A single tap on the glowing plane goes straight to the reef (`:333-335`, `kind == "reef"` activates on first tap).

## Time budget
- Total (to the landing prompt, per opening): (a) 20 / 45 / 120 s (max includes a reef detour); (b) 18 / 40 / 100 s; (c) 8 / 15 / 25 s from the first gold tap to the new Day One lagoon, of which the irreversible wipe takes 2–4 s; (d) as (a)/(b), except d4' which is unbounded in the castle (minutes) unless she stumbles into the reef attic.
- Longest passive span: (c3) the scene reload — full `_ready` world rebuild behind the splash + 0.45 s fade (`main.gd:986-1078`, `boot_splash_overlay.gd:9,36`); 2–8 s inferred, unmeasurable here. On a 3–4-year-old phone the max lands in "taps the screen / looks away".
- Longest input-required span with no new feedback: d4' (no exit prompt at all); otherwise the runway-to-castle walk in (a)/(b): ~8–25 s with the only pointer facing the reef (`sky_lagoon_promenade.gd:1077-1083`).
- Natural stopping points that lose nothing: any moment — milestones write synchronously (`main.gd:3949-3959`), hot sites debounce 1.5 s (`:3983-3988`), backgrounding flushes both (`:4353-4357`). Caveat: Continue never resumes position — it always restarts at the runway end (`main.gd:3971-3972`), so "stopping in the pool" costs the walk back but no progress.

## Pros (as this player experienced it)
- Continue is one tap and lands in a lively, familiar place with a recorded Roshan line and a glowing target (`sky_lagoon_promenade.gd:1077-1083`; `audio_director.gd:169-173`).
- Once inside, the castle's four-state door language is consistent: exactly one golden door, fog on the rest, a blocked tap always answers with sound + banner + Roshan's voice (`castle_rooms_25d.gd:1695-1718`, `castle_door_language.gd`).
- The elevator picture map with its bobbing gold "▼" is an effective non-reader pointer that reveals the golden room without walking (`castle_rooms_25d.gd:1248-1271`).
- Partial-save normalisation is monotonic and order-safe: room order is re-derived, the art desk is derived from actions, pool progress restores exactly (`day_one_director.gd:539-629`; `probe_day_one_director.gd:99-114`).
- Re-entering the finished bathroom re-offers the pool picture with a ghost hand (`main.gd:7562-7637`).
- The save transaction machinery (temp → verify → install, `.bak`, generation ordering, future-schema read-only) genuinely protects data (`save_state.gd:694-786`; `scripts/probe_save_recovery.gd`).

## Cons / friction (as this player experienced it)
- (a) Her old, fully unlocked castle is silently converted into Day One on the first boot of this build — before she taps — because normalisation defaults `day_one_active` to true and the loader repairs the file (`save_state.gd:82-86, 430, 439, 526-530`; `day_one_director.gd:597-598`). The Opera door she came for says "resting" (`castle_rooms_25d.gd:1712-1718`).
- (b) Continue on an active Day One lands at the far end of the lagoon with the castle off-screen and the only pointer/voice aimed at the reef (`main.gd:3971-3972`; `sky_lagoon_promenade.gd:261, 991-997, 1077-1083`). A tap on the glowing plane leaves Day One on the first tap (`:333-335`).
- (b) In the hall the golden door is off-screen at entry (art x 2340 vs view 0..1672; `castle_rooms_25d.gd:86, 152-191, 2318-2323`), while four fogged doors are on-screen inviting a blocked tap.
- (c) A gold button followed by a same-style gold button 168 px away, no voice, no pointer, focus pre-placed on the destructive choice, no delay — two casual taps wipe the family save (`start_menu.gd:81-82, 233-234, 256-264, 271-275`).
- (c) "Your saved adventure will be kept for a grown-up to restore" is text a non-reader cannot see and a promise the tooling does not keep (`start_menu.gd:222`; `backup.sh:64-68`; `BACKUP.md:62-71`).
- (c) After the wipe the child watches a full rebuild behind the splash (unbounded on this phone), then the runway plane "arrives" by vanishing at 7.0 s (`sky_lagoon_promenade.gd:1038-1068`).
- (a) Two banners fire in the same frame on castle entry; "Dust bunnies! This castle needs our help!" is never seen (`main.gd:6845, 7784-7785` vs `6847-6859`).
- Daddy Mermaid's hint lines have no recording; every blocked door plays a pitched "yay" before Roshan's generic "talk" (`audio_director.gd:22-27, 43-47, 117-126`).
- (d4') A kill during the boss leaves a clean, locked, pointer-less castle with no in-Day-One re-arm.
