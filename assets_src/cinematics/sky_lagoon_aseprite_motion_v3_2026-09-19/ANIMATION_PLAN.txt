SKY LAGOON — THREE-SCREEN ANIMATION PLAN v3 / 2026-09-19
Owner direction: Aseprite authors the bridge animation. Do not substitute a shader or whole-image wobble. This plan supersedes the v14 bridge/water recommendations for this workstream. The rejected castle-motion-trial-v1 is diagnostic history, never the quality target.

1. CREATIVE VISION
One gently breathing garden with a clear hierarchy: Roshan and intentional interactions first, nearby plants second, distant world nearly still. Retain the exact v16 geography, castle portrait, four towers, bridge anchors, left screen connector and descending path. Foreground huckleberry and background shrubs share botanical language. Sparse cream bells and a very limited hydrangea accent retain diversity. No synchronized bouquet wobble, random flashing, moving mountains, rubber castle or swimming paths.
Do not divide work into equal asset counts. Split by the kind of drawing and temporal judgment each motion requires.

2. OWNERSHIP MATRIX
G01 CASTLE BRIDGE DECK | Grok reference -> Aseprite authored RGBA frames -> Godot event playback. First priority. One local load, a small board flex, release and settle. Supports and both landings fixed. No invisible permanent depression, no whole-bridge bounce. 8-12 deliberately drawn frames across about 0.8-1.2s; timing adjusted after the reference review. Author separate near/middle/far contact variants if a single local response cannot follow Roshan's footsteps.
G02 CASTLE BRIDGE CHAIN | Grok reference -> Aseprite secondary-action cels in the same bridge file. Second priority. One existing chain span reacts after deck contact and settles. Preserve link count and both attachment sockets. Do not commission a separate chain clip until G01 timing is useful. 6-10 authored states, offset approximately 60-120ms from contact; test rather than canonize that offset.
G03 WATER SURFACE | Grok reference -> Aseprite painted alpha highlight loop. Castle first, then arrival palette/scale adaptation. Third priority. Two or three broad overlapping highlight bands change shape and travel coherently; base water colour stays stable. Author a small tile or bounded patch, not a full-scene video atlas. 8-12 distinct frames, initially 256x128 or 256x256. A 1s reference is one motion phrase, not automatically a seamless loop.
G04 SHORELINE LAP | Grok reference -> Aseprite thin alpha sequence behind fixed stones. Arrival pool first; adapt only where castle shoreline actually meets water. Fourth priority. One advancing/receding painted line, no white ocean surf. 8-10 frames, approximately 0.8-1.4s, local rock occlusion mask. Do not smear shore pixels to fake lapping.
G05 TOUCH RIPPLE | Grok reference -> Aseprite one-shot expanding elliptical rings. Arrival/castle water only. Fifth priority. 6-10 authored frames, about 0.6-1.0s; starts at the actual touch point, fades naturally, no reward or saved progress. Clip behind bridge/rocks. Keep independent of ambient highlights.

K01 HUCKLEBERRY | local Krita master + Image Gen 2 missing pose/overlap candidates. All screens. Start with one three-branch shrub. Preserve berry count, root and leaf attachment. Build rest, soft bend, strongest bend and return drawings; refine intervening frames in Krita. Animate one branch group at a time, with small delayed leaf response. Aseprite may package accepted frames, but no Grok commission is needed until a specific motion problem survives local drawing review.
K02 FLOWER STEMS | local Krita + Image Gen 2 poses. Arrival cream bells and sparse meadow hydrangea; castle cream bells. Separate stem/leaves from flowerhead only where overlap is fully painted. Draw a modest bend and a lagging head, root fixed. Keep bloom colour constant. 4-6 useful drawings over a slow 3-5s idle; long quiet intervals are intentional environmental stillness. Optional touch response gets its own short settle clip.
K03 ARRIVAL CONIFER | local Krita + Image Gen 2 hidden branch repairs and one near branch pose. Trunk and silhouette footprint remain fixed. Only two or three nearest tips move; do not animate the entire tall tree. Do this after K01 proves coherent. Separate painted sky behind each moving branch before integration.
K04 CASTLE GLINT/WINDOW | local Krita effect cels. One small gold glint or warm window accent with long irregular quiet intervals. Keep the portrait untouched. Draw 4-6 small alpha frames (64-128px), no global relighting or neon bloom. Do not repeat the same glint over every turret.
STATIC FOR NOW | mountains, cabins, paths, bridge foundations, castle masonry/portrait, far forest and most ground cover. Cloud drift is deferred until foreground motion is accepted; a moving cloud sea could overwhelm the scene. Door opening is a later functional interaction requiring hinges, interior and navigation ownership, not ambient garnish.

Current v16 ORAs have only four broad foreground-review layers per screen. These targets are future production work; do not call the existing files fully separated or animation-ready.

4. GROK EXECUTION
Use the five cards in priority order; one tiny action per request, locked camera, silence. Request the shortest duration actually supported by the chosen surface: API currently documents 1s minimum; website minimum remains unverified. GitHub is delivery, not the generation interface. Cards default to 1s reference phrases. If the interface requires longer, hold the settled state for the remaining time and record the actual duration. Do not slow the action to fill time. No multi-shot full-scene video.
IMAGE_1 is a native scene crop, IMAGE_2 a material detail. Single-image I2V uses IMAGE_1 only; IMAGE_2 remains an operator reference unless the selected reference mode can preserve an exact first frame. Preserve input aspect, never stretch. The board is a planning contact sheet of source stills, not generated action evidence and never a pixel input. No character is needed for these material studies; an actual Roshan crossing is a later gameplay test using her approved actor.
The repository ready-card validator/template still assumes 2-8s/16:9 delivery. These 1s native-aspect ENVIRONMENT MOTION REFERENCE cards are intentionally DRAFT, with the mismatch recorded. Do not mark GENERATION_READY until that scoped contract is reconciled and exact bindings/interface are accepted. This archive contains executable prompt drafts, not a claim that the old ready gate passed. No validator is weakened in this change.

5. ASEPRITE BRIDGE PRODUCTION — REQUIRED, NOT OPTIONAL
Keep one RGBA .aseprite source with named layers: reference_locked (hidden on export), rear_chain, supports_fixed, deck_boards, front_chain, front_posts, contact_shadow. Draw complete overlap under chain/deck movement. Paint a clean world plate behind the bridge; never leave a painted duplicate beneath exported moving parts.
Rest frame must composite exactly into the accepted scene. Establish board seams, four landing corners, post caps and chain sockets as measured landmarks. Keep supports/landings at identical coordinates across all frames; intended deck deflection must be local and very small. Draw shapes and shading for the changed state; do not deform a flattened bridge patch as the final animation.
Tags: rest; step_near; step_mid; step_far, only after each variant exists. One-shot timing: contact -> compression -> release -> diminishing settle -> exact rest. No autonomous looping of footsteps. Godot selects the contact variant from Roshan's real footfall location and fires at most once per contact event. Transit direction and nearer railing occlusion must remain correct. Repeated contacts cannot stack unbounded motion.
Grok output is a timing/shape reference on a non-export layer. Inspect every generated frame; reject invented links, changing post count, melting wood, camera drift or foot contact that cannot be reproduced. Do not automatically turn an MP4 into a shipped atlas. Author accepted RGBA cels and keep references and final pixels explicitly separate.
Export PNG atlas + JSON with names, rectangles, frame durations and tags. Retain stable canvas/origin; disable trim initially. If trimming is later introduced, preserve and validate sourceSize/spriteSourceSize offsets. Use transparent padding, inspect edges on dark/light/scene backgrounds, and prevent bilinear atlas bleeding. Export only visible delivery layers, never the reference layer. Keep native .aseprite and a reproducible batch command beside outputs.

6. LOCAL KRITA / CODEX BUILT-IN IMAGE GENERATION WORK
Use Codex built-in image generation for missing drawings and clean overlap, not as a temporal interpolator. Generate one candidate pose per call with the same source/reference and explicit root/landmark locks; inspect and reject drift before spending on further frames. Keep each native candidate, exact prompt, model, dimensions and hash. Krita assembles, corrects edges, harmonizes palette and supplies frame drawing/onion-skin comparison. Generated images alone are not a finished animation.

Generate through Codex and copy native results into the local versioned source folder. Krita-compatible ORA files and masks remain editable without desktop input automation.
Keep native generated opaque backing if the model does not return alpha; separate it with a reviewed mask and retain original pixels. Never silently substitute another image model. Current owner authorizes local masks/packaging. Work through files/batch APIs, not desktop mouse automation while the owner uses the computer.

7. IMPLEMENTATION AND ACCEPTANCE
Prototype one bridge contact sequence and one plant phrase separately before all-scene expansion. Retire the simplistic shader bridge trial as a rejected look. In Godot use AnimatedSprite2D/SpriteFrames or AnimationPlayer for frame playback and events; Godot owns contact, pause, focus loss, scene exit and offscreen culling. Preserve one source of gameplay state. Ambient animation never awards progress or writes save data.
Keep water, bridge and plant effects independently switchable. Pausing freezes clocks; scene exit cancels transients; returning starts in stable rest. No frame queues accumulating during a pause. Static original is a reversible fallback.
Performance: Mobile renderer, exact Godot 4.7.2, 30fps target on Lenovo Tab M11. Source art is 1254 square review art, below native 2048-per-screen production coverage. Use small local effect crops, power-of-two atlas pages or <=1024 longest-edge textures. Calculate decoded bytes from actual atlas dimensions (RGBA 4 bytes/pixel before mips); never assume compression or a 1024 page is free. Example bridge crop 384x256 x 10 frames ~3.75MiB before padding/mips, versus 40MiB for ten 1024 square frames. Measure the actual packed result and transparent overdraw.
Review at actual phone scale and full-frame context: fixed anchors, no duplicated objects, correct occlusion, calm palette, continuous plant anatomy, unblocked paths, no loop pop, no whole-scene brightness pumping. Machine gates do not grant 4.9/5. Owner look acceptance, target device and child readability remain separate.
